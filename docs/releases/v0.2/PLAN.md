검토자는 지정 제품 소스, `backlog.json`의 Phase별 `adversarialFocus`, `specRefs`만 읽는다. 세션 대화, 구현 근거, 문서·설정·테스트 산출물, Git 정보, 셸 도구는 검토 컨텍스트에서 제외한다. 결과는 `docs/releases/v0.2/reviews/A{n}.md`에 Critical/Major/Minor, 재현 조건, SPEC 조항, 처리 상태를 기록한다. Critical 수정 뒤에는 같은 반대 벤더 검토를 재실행한다.

## Phase 1. 파일 접근 기반과 상태 확장

### 목표

v0.2의 지원 파일과 상대 리소스를 안전하게 처리할 수 있도록 main process 파일 접근 API와 창별 상태 모델을 확장한다.

### 작업 범위

- 지원 확장자와 `markdown`, `text`, `code`, `empty` 탭 종류 정의
- Root Folder 내부 텍스트·코드 파일 읽기 API 확장
- 파일 크기 상한, 바이너리 징후, 지원하지 않는 인코딩을 구분하는 오류 결과 정의
- 상대 이미지와 Markdown 링크 대상의 Root 경계 검증 API 구성
- `rootPath`, `currentDirectoryPath`, `tabs`, `activeTabId`, `explorerVisible`, `explorerWidth`, `focusMode`, `contentFontScale`의 창별 상태 모델 확장
- Renderer, preload, main process의 최소 권한 경계 유지

파일 읽기 응답은 내용과 함께 `kind`, `language`을 반환하고, 지원 파일과 직접 실행 인자는 종류와 관계없이 `10 MiB` 상한 및 바이너리·인코딩 검증을 적용한다. 상대 리소스는 기준 Markdown 파일과 상대 경로를 받은 제한된 API로만 검증한다.

### 완료 기준

- Renderer는 preload가 공개한 API로만 파일과 클립보드 기능을 요청한다.
- 지원 파일의 종류와 언어를 일관되게 판별할 수 있다.
- Root 밖, 대용량, 바이너리, 지원하지 않는 인코딩 요청을 구조화된 오류로 구분한다.
- 창마다 Root와 UI 상태가 독립적으로 유지된다.

## Phase 2. Root 기반 Explorer

### 목표

사용자가 Root Folder 범위 안에서 현재 디렉터리의 지원 파일과 폴더를 안전하게 탐색할 수 있게 한다.

### 작업 범위

- `Open Folder`로 Root Folder를 선택하고 취소 시 기존 상태 유지
- `currentDirectoryPath`의 직접 자식만 표시하는 목록형 Explorer 구현
- 목록 첫 항목 `..`, Root에서의 비활성화, 부모 폴더 이동 구현
- 폴더 우선·이름순 정렬과 지원 파일 확장자 필터링
- 클릭, `↑`, `↓`, `←`, `→`, Enter 기반 탐색과 실행
- 선택·포커스·hover 상태 구분 및 Root·권한 오류 표시

### 완료 기준

- Explorer가 재귀 트리가 아닌 현재 디렉터리 목록으로 동작한다.
- Root 밖으로 이동하거나 Root 밖 파일을 표시·열 수 없다.
- 키보드와 마우스로 폴더 이동 및 지원 파일 선택을 수행할 수 있다.
- Folder Picker 취소와 파일 시스템 오류가 기존 정상 상태를 불필요하게 변경하지 않는다.

## Phase 3. 탭과 파일 열기 규칙

### 목표

빈 탭과 파일 탭을 포함한 다중 문서 열람 흐름을 SPEC의 일관된 규칙으로 제공한다.

### 작업 범위

- 탭 없는 초기 화면과 `+`, `Ctrl+T` 기반 빈 탭 생성
- 파일 열기 전 경로·확장자 검증과 내용 읽기 연결
- 동일 절대 경로 탭 활성화 및 중복 탭 생성 방지
- 활성 `empty` 탭의 파일 탭 전환과 새 파일 탭 생성 규칙 구현
- 탭 선택·닫기, 인접 탭 활성화, `Ctrl+Tab`, `Ctrl+Shift+Tab` 순환 전환
- 일반 `Tab` 키는 화면 컨트롤 포커스 이동에만 사용

### 완료 기준

- 인자 없는 시작과 마지막 탭 닫기는 탭 없는 빈 화면으로 전환된다.
- 같은 파일을 다시 열어도 새 탭이 생성되지 않는다.
- 파일 읽기 실패가 기존 탭의 정상 내용을 덮어쓰지 않는다.
- 탭 전환 단축키와 키보드 포커스 규칙이 충돌하지 않는다.

## Phase 4. 문서·코드 렌더링

### 목표

Markdown, 텍스트, 코드 파일을 읽기 전용으로 표시하고 문서 내부의 안전한 로컬 리소스 탐색을 제공한다.

### 작업 범위

- `react-markdown`과 `remark-gfm` 기반 Markdown·GFM 렌더링
- 지원 언어의 Markdown 코드 블록과 코드 뷰어 문법 하이라이트
- 텍스트·코드 읽기 전용 뷰어와 코드 블록·코드 뷰어 Copy 버튼 구현
- 상대 경로 로컬 이미지의 허용 형식·존재·Root 경계 검증과 오류 표시
- 상대 `.md` 링크의 앱 내부 파일 열기 연결
- 빈 파일, 렌더링 실패, 복사 성공·실패 상태를 영어 UI로 표시

### 완료 기준

- Markdown과 GFM의 필수 요소가 GitHub Markdown 계열 스타일로 표시된다.
- 지원 텍스트·코드 파일은 Markdown Renderer가 아닌 읽기 전용 뷰어로 열린다.
- Copy는 파일을 변경하지 않으며 성공·실패 상태를 구분한다.
- Root 밖, 누락, 미지원 형식의 이미지·링크는 열지 않고 오류 상태를 표시한다.

## Phase 5. Explorer와 일반 화면 UI

### 목표

Explorer와 탭·상태바를 compact하고 접근 가능한 일반 보기 화면으로 완성한다.

### 작업 범위

- 영어 `Open`, `Reload` 헤더 버튼과 파일·폴더 표시 구성
- SVG 아이콘 적용 시 영어 tooltip과 접근 가능한 이름 제공
- Explorer 표시·숨김과 창 안에서만 유지되는 마지막 폭 복원
- 세로 구분선 드래그, 최소 `12rem`, 기본 `17rem`, 최대 창 너비 45% 제한
- 드래그 중 `col-resize` 커서와 텍스트 선택 방지
- 고정 탭 영역과 일반 보기 상태바의 활성 파일 전체 경로 표시

### 완료 기준

- Explorer 폭은 정의된 범위를 넘지 않으며 숨김 후 다시 표시해도 마지막 폭을 사용한다.
- Explorer 키보드 선택·포커스와 마우스 hover가 시각적으로 구분된다.
- 탭 영역은 문서 스크롤과 함께 이동하지 않는다.
- 일반 보기 상태바가 파일 경로 또는 경로 없음 상태를 영어로 표시한다.

## Phase 6. 테마·가독성·집중 보기

### 목표

Light/Dark 테마와 읽기 영역 중심의 가독성 기능을 제공하고, 집중 보기 전환 시 일반 레이아웃을 정확히 복원한다.

### 작업 범위

- 최상위 `data-theme`와 CSS 사용자 정의 속성 기반 Light/Dark 테마
- Markdown, 코드 블록, 코드 뷰어의 GitHub Light/Dark 계열 스타일
- 콘텐츠 영역 전용 `contentFontScale`과 키보드·마우스 휠 단축키
- `F11` 기반 focusMode 전환 및 운영체제 전체화면 API 미사용
- 집중 보기에서 문서 영역만 표시하고 일반 보기의 Explorer 상태·폭 복원

### 완료 기준

- 테마 전환이 별도 화면 없이 CSS 변수로 일관되게 적용된다.
- 글꼴 크기 조절은 콘텐츠에만 적용되고 Explorer·탭·버튼·상태바 레이아웃을 바꾸지 않는다.
- 집중 보기에서 `Ctrl+Tab`과 `Ctrl+Shift+Tab` 탭 전환이 계속 동작한다.
- 집중 보기 해제 시 이전 Explorer 표시 상태와 폭이 복원된다.

## Phase 7. 수동 Reload와 오류 복구

### 목표

자동 파일 감시 없이도 사용자가 변경 사항을 안전하게 반영하고 파일 시스템 오류에서 작업 상태를 유지할 수 있게 한다.

### 작업 범위

- `Reload`, `Ctrl+R`, `F5`의 단일 수동 Reload 동작 구성
- 현재 Explorer 목록과 활성 파일 탭만 다시 읽는 범위 적용
- 활성 파일 삭제, 현재 디렉터리 삭제, Root 삭제·이동, 권한 오류 처리
- `NOT_FOUND`, `ACCESS_DENIED`, `OUTSIDE_ROOT`, `ROOT_UNAVAILABLE` 영어 오류 상태 표시
- 자동 감시, debounce 감시, 백그라운드 재읽기가 추가되지 않는지 확인

### 완료 기준

- Reload가 현재 디렉터리와 활성 파일만 갱신하며 비활성 탭을 다시 읽지 않는다.
- 파일·폴더 삭제와 권한 오류가 앱 비정상 종료로 이어지지 않는다.
- Root를 사용할 수 없으면 Explorer를 비우고 명확한 상태를 표시한다.
- 기존 성공 상태를 유지할 수 있는 오류에서는 정상 내용을 유지한다.

## Phase 8. 통합 검증과 패키지 확인

### 목표

v0.2 기능의 보안 경계와 Windows 실행 흐름을 통합 검증하고 배포 환경에서 회귀가 없는지 확인한다.

### 작업 범위

- Root 경계, 심볼릭 링크·junction, IPC 입력 검증 회귀 확인
- Explorer, 탭, 렌더링, 테마, Reload의 핵심 사용자 흐름 수동·자동 검증
- Windows Explorer의 `.md` 직접 실행과 창별 Root·탭 상태 격리 검증
- Windows 설치 또는 실행 패키지 생성과 `.md` 파일 연결 설정 확인
- 설치 환경에서 Open Folder, 파일 열기, 탭, 렌더링, Reload, 직접 실행 검증
- 버전, 아이콘, 배포 산출물 정리

### 완료 기준

- Root 밖 접근과 링크 우회가 모든 파일 접근 경로에서 차단된다.
- 직접 실행한 `.md` 파일은 부모 폴더를 Root로 하는 독립 창에서 열린다.
- Windows 11에서 설치 또는 실행 가능한 v0.2 배포 산출물이 생성된다.
- 설치 환경에서 v0.2 핵심 요구사항과 v0.1 직접 실행 흐름이 동작한다.

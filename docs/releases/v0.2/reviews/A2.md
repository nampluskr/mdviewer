## 2차 검토

Critical 수정 후 동일 범위로 재실행했다. Claude 응답은 심각도별 요약만 반환하여 요청한 재현 조건과 명세 조항을 항목별로 제공하지 않았다.

| 심각도 | 건수 |
|---|---:|
| Critical | 1 |
| Major | 3 |
| Minor | 2 |

| 심각도 | 지적 | 처리 상태와 근거 |
|---|---|---|
| Critical | 상대 Markdown 링크가 외부 링크 처리로 전달되어 동작하지 않음 | 유효하지 않음. PRD FR-25와 SPEC 6.4는 Phase 04 범위이며, 이번 검토의 PRD FR-01~FR-13 및 SPEC 3.1~4.4 범위 밖이다. |
| Major | 검증 뒤 symlink 교체 TOCTOU 가능성 | 잔여 위험 기록. 1차 검토와 동일한 Node.js 경로 API 한계이며, Root identity 재검증으로 Root 교체 공격은 차단한다. |
| Major | 사라진 Root가 `NOT_FOUND`로 보고될 수 있음 | 수정 완료. Root 검증 실패는 `ROOT_UNAVAILABLE`로 분류하며 권한 오류만 `ACCESS_DENIED`로 분류한다. |
| Major | Folder Picker Promise 거부를 처리하지 않음 | 수정 완료. main process와 Renderer 모두 대화상자 실패를 잡아 기존 상태를 유지하고 영어 오류를 표시한다. |
| Minor | Root 식별자가 선언되지 않은 IPC 데이터로 전달됨 | 수정 완료. 초기 파일 IPC 응답에서는 공개 필드만 반환한다. |
| Minor | 부모 창 없는 비모달 Folder Picker 가능성 | 유효하지 않음. BrowserWindow를 찾을 수 없는 경우는 Renderer가 없는 비정상 호출이며, 정상 IPC는 송신 창을 부모로 사용한다. |

## 결론

유효한 Critical은 모두 수정했다. Major와 Minor의 처리·이관·기각 근거를 위 표에 기록했다. Root identity를 교체하는 junction 또는 symbolic link 공격에 대한 재검토 범위의 Critical은 해소되었다.

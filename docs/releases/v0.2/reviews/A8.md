## 검토 결과와 처리

| 심각도 | 지적 및 재현 조건 | 관련 조항 | 처리 상태 및 근거 |
|---|---|---|---|
| Critical | `\\server\\share\\lure.md` 또는 `\\?\\UNC\\server\\share\\lure.md`를 직접 실행 인자로 넘기면 시작 중 SMB 접근이 발생한다. | PRD NFR-04~NFR-06, SPEC 3.1~3.2 | 수정 완료. 파일시스템 접근 전에 UNC 형식 직접 실행 인자를 거부하는 `isLocalMarkdownLaunchArgument`를 추가했고, UNC·확장 UNC 회귀 테스트를 통과했다. |
| Major | SMB로 매핑된 드라이브 문자(`Z:\\notes.md`)는 로컬 절대 경로 형식을 만족해 직접 실행될 수 있다. | PRD FR-03, NFR-04~NFR-06 | 잔여 위험. v0.2의 직접 실행 정의는 표준 로컬 절대 경로와 UNC 차단이며, Node.js만으로 드라이브 문자의 원격 매핑 여부를 안정적으로 판별하지 않는다. 파일 읽기 뒤 Root 실경로·경계 검증은 계속 적용된다. |
| Minor | 드라이브 없는 `\\notes.md`가 현재 작업 드라이브 기준으로 해석될 수 있다. | PRD FR-03, NFR-04~NFR-05 | 잔여 위험. Windows 경로 해석 규칙에 따른 경계 사례이며, 일반 Explorer 파일 연결은 드라이브 문자가 있는 정규 절대 경로를 전달한다. |
| Minor | CSP의 `img-src file:`이 향후 DOM 주입 취약점이 생기면 임의 로컬 이미지 요청의 방어 심도를 낮춘다. | SPEC 3.1~3.2, NFR-04~NFR-06 | 잔여 위험. 현재 Markdown은 raw HTML을 렌더링하지 않고 상대 이미지 경로는 main-process Root 검증을 거친다. 검증된 로컬 이미지 표시 기능을 유지하기 위해 `file:`을 허용한다. |
| Minor | `stat`의 크기 검사와 `readFile` 사이에 파일이 교체·증가할 수 있다. | SPEC 3.1~3.2 | 잔여 위험. Node.js 경로 기반 API의 TOCTOU 한계이며, Root identity와 대상 실경로를 매 요청에 재검증한다. |
| Minor | UTF-16 파일은 NUL byte 때문에 바이너리 파일로 분류된다. | SPEC 3.1~3.2 | 유효하지 않음. SPEC은 UTF-8 fatal decoding을 기준으로 하며 UTF-16 지원을 요구하지 않는다. |

## 결론

유효한 Critical은 모두 수정했고 동일 반대 벤더의 재검토에서 Critical 0건을 확인했다. Major와 Minor의 처리 근거 및 남은 위험은 위 표에 기록했다.

## 3차 최종 결과

Claude Sonnet은 3차 실행에서 항목별 재현 조건과 명세 조항을 반환하지 않고 요약만 반환했다. 다음은 반환된 지적과 main agent의 처리 근거다.

| 심각도 | 지적 | 처리 상태 및 근거 |
|---|---|---|
| Major | 직접 실행 인자가 `.md`만 허용하므로 다른 지원 파일 형식의 파일 연결 실행이 실패할 수 있다. | 유효하지 않음. PRD FR-28은 Windows 파일 연결을 `.md`에만 적용하고, SPEC 5.3도 `.md` 직접 실행만 정의한다. |
| Minor | 여러 직접 실행 인자에서 첫 번째 `.md`만 선택한다. | 유효하지 않음. PRD FR-29와 SPEC 5.3은 단일 `.md` 직접 실행의 새 창 동작만 요구한다. |
| Minor | 경로 검증과 파일 읽기 사이에 TOCTOU 창이 있다. | 잔여 위험. 2차 검토와 동일한 Node.js 경로 기반 API 한계이며, Root identity와 대상 실경로를 매 요청에 재검증한다. |
| Minor | 단일 인스턴스 잠금이 없어 직접 실행마다 새 프로세스가 생긴다. | 유효하지 않음. SPEC 5.3은 기존 창 재사용이나 single-instance 전달을 강제하지 않는다고 명시하며, 창별 상태 격리를 요구한다. |

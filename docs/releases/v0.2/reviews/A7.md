## 실행 이력

초기 실행은 Critical 1건, Major 2건, Minor 2건의 개수만 반환해 세부 처분이 불가능했다. 이후 두 번은 샌드박스의 Anthropic API egress 차단으로 실패했다. 사용자 승인 후 샌드박스 외부에서 검토를 재실행했다.

첫 번째 원문 검토의 Critical은 Reload 중 폴더 이동 시 이전 목록 응답이 새 목록을 덮어쓰는 경쟁 상태였다. `loadDirectory`가 진행 중인 Reload 버전을 무효화하도록 수정했고, Root 불가 시 활성 탭에도 오류를 표시하도록 보완했다. 재검증 후 같은 검토를 재실행했다.

## 최종 검토 결과 및 처분

| 심각도 | 지적 | 재현 조건 | 관련 조항 | 처리 상태 및 근거 |
|---|---|---|---|---|
| Critical | Root 폴더 자체를 삭제한 뒤 Reload하면 `NOT_FOUND`로 남아 Explorer 초기화가 되지 않음 | Root에서 폴더를 삭제하고 `F5` 실행 | PRD FR-22, SPEC 3.1-3.3 | 유효하지 않음. Main process의 `resolvePathWithinRoot`는 경로 확인 전에 `verifyRoot`를 수행한다. 삭제된 Root는 `ROOT_UNAVAILABLE`으로 반환되며 Renderer의 초기화 분기가 실행된다. |
| Major | 현재 하위 폴더의 권한 오류에서 Root로 복구하지 않음 | 하위 폴더 권한을 제거한 뒤 Reload | PRD FR-26-FR-27 | 유효하지 않음. SPEC 7.2는 권한 오류 시 기존 성공 상태를 유지하고 실패 대상에 `ACCESS_DENIED`를 표시하도록 정의한다. Root 복구는 현재 디렉터리 삭제 시에만 요구된다. |
| Major | 비활성 탭이 자동 재검증되지 않음 | 비활성 탭의 파일을 변경·삭제한 뒤 탭 전환 | PRD FR-22, FR-26-FR-27 | 유효하지 않음. SPEC 7.1은 Reload가 활성 탭에 연결된 파일만 다시 읽도록 명시하며, 비활성 탭의 자동 감시·재읽기를 금지한다. |
| Major | Root 불가 후 열린 탭의 상대 링크가 IPC를 요청할 수 있음 | Root 불가 상태의 Markdown 링크 클릭 | SPEC 7.1-7.2, NFR-04-NFR-06 | 유효하지 않음. Renderer는 제한된 preload API만 호출하며, Main process가 매 요청마다 Root 존재·실경로·경계 검증을 수행한다. 검토 범위 제한으로 Main process 검증을 확인하지 못한 조건부 추정이다. |
| Minor | 빈 탭에서 두 파일 열기 요청이 경합할 수 있음 | 같은 빈 탭에서 빠르게 두 파일 열기 | SPEC 3.1-3.3 | 범위 외. 기존 파일 열기 비동기 처리의 잠재 경합이며 Phase 7의 Reload·오류 복구 변경으로 도입되지 않았다. |

## 남은 위험

Renderer 단위 테스트 환경이 없어 실제 Electron UI에서 삭제·권한 변경을 자동화해 재현하지는 않았다. Main process의 구조화된 오류 변환과 Root 경계 검증은 기존 단위 테스트 및 이번 TypeScript·빌드 검증으로 회귀 여부를 확인했다.

# BRIEF.md — Markdown Browser v0.2

> 문서 위치: `docs/releases/v0.2/BRIEF.md`
> 문서 역할: 무엇을, 왜 만드는가. v0.2의 제품 의도와 검토 출발점을 정의한다.
> 후속 문서: `PRD.md` → `SPEC.md` → `PLAN.md` → `backlog.json`

---

## 1. 프로젝트 의도

Markdown Browser는 Windows에서 로컬 Markdown 문서를 탐색하고 읽기 위한 경량 데스크톱 애플리케이션이다.

사용자는 하나의 Root Folder를 선택하고 그 하위 폴더의 Markdown 문서를 Explorer에서 찾는다. 선택한 문서는 탭으로 열고, 여러 문서를 전환하며 읽는다. Windows Explorer에서 `.md` 파일을 직접 실행한 경우에는 해당 파일의 부모 폴더를 Root Folder로 사용해 독립 창에서 연다.

이 제품의 목적은 Markdown 편집기나 범용 파일 관리자가 아니라, 프로젝트와 문서 폴더의 Markdown을 빠르게 탐색하고 열람하는 전용 Browser를 제공하는 것이다.

## 2. 제품 원칙

- **읽기 전용**: 원본 Markdown 파일을 임의로 수정하지 않는다.
- **로컬 우선**: 핵심 기능은 인터넷 연결 없이 동작한다.
- **범위 제한**: 파일 탐색과 읽기는 선택한 Root Folder 및 그 하위 경로로 제한한다.
- **보안 경계**: React Renderer는 Node.js 파일 시스템 API에 직접 접근하지 않으며, preload와 Electron IPC를 경유한다.
- **단순한 열람 경험**: Explorer, 탭, Markdown 렌더링에 집중하고 불필요한 편집·관리 기능을 포함하지 않는다.
- **창별 독립성**: 각 Browser Window는 Root Folder, Explorer 상태, 탭, 활성 탭을 다른 창과 공유하지 않는다.
- **UI 언어**: 앱의 화면 텍스트, 버튼, 상태 메시지, tooltip은 영어로 표시한다.

## 3. 현재 사용 흐름

```text
Markdown Browser 실행
  → Root Folder 선택 또는 .md 파일 직접 실행
  → Explorer에서 Root 하위 Markdown 문서 탐색
  → 활성 탭에서 문서 열기
  → 여러 탭 사이를 전환하며 Markdown과 GFM 내용 열람
```

탭이 없는 초기 상태와 마지막 탭을 닫은 상태에서는 빈 화면을 표시한다. 사용자는 `+` 버튼으로 새 빈 탭을 만든 뒤 Explorer에서 문서를 선택할 수 있다.

## 4. v0.1에서 유지하는 핵심 범위

- Root Folder 선택 및 하위 Markdown 탐색
- 현재 디렉터리 목록 기반 Explorer와 표시/숨김
- 다중 탭, 빈 탭 생성, 탭 전환과 닫기
- Markdown 및 GitHub Flavored Markdown 렌더링
- Windows `.md` 파일 연결과 직접 실행
- 직접 실행 파일의 부모 폴더를 Root Folder로 설정
- 파일 실행마다 독립 Browser Window 생성
- Root 경계 검증과 파일 시스템 오류 표시

## 5. 범위 밖 기능

v0.2의 개선 요구가 확정되기 전까지 다음 기능을 제품 목적에 포함하지 않는다.

- Markdown 편집
- 문서 생성·삭제
- Git 기능
- 터미널 또는 코드 실행
- 범용 파일 관리 기능
- 클라우드 동기화
- macOS 및 Linux 지원

## 6. v0.2 검토 출발점

v0.2의 구체적인 범위는 v0.1 결과에 대한 사용자의 검토 후 정한다. 이 문서에는 검토에서 확인된 사용성, 안정성, 성능, 보안 경계, 렌더링 품질의 개선 요구만 추가한다.

검토 전에는 새로운 기능, 기술 선택, 구현 Phase를 확정하지 않는다. 확정된 요구는 이 문서에서 제품 의도로 먼저 반영한 뒤 `PRD.md`, `SPEC.md`, `PLAN.md`, `backlog.json`으로 구체화한다.

## 8. v0.1 사용자 검토 기반 개선 요구

### 8.1 문서와 탭 영역

- 문서를 아래로 스크롤하는 동안에도 탭 영역은 창 상단에 고정되어야 한다.
- 탭 영역의 높이는 현재보다 줄여 약 `2rem` 수준의 조밀한 높이로 표시되어야 한다.

### 8.2 Explorer 사용성

- Explorer는 글꼴, 여백, 항목 높이를 포함해 VS Code와 유사한 compact하고 dense한 스타일로 표시되어야 한다.
- Explorer 상단에는 전체 폭의 강조 버튼 대신 조밀한 헤더를 두고, `Open`과 `Reload`를 영어 텍스트 버튼으로 표시해야 한다.
- 파일·폴더 아이콘을 적용하는 단계에서는 `Open`과 `Reload`를 VS Code와 유사한 SVG 아이콘 버튼으로 바꾸고, 영어 tooltip과 접근 가능한 이름을 제공해야 한다.
- Explorer 헤더의 버튼은 평소 투명한 배경을 사용하고, 마우스 hover 또는 키보드 포커스일 때만 약한 배경색을 표시해야 한다.
- 사용자는 Open Folder 또는 수동 Reload 동작으로 Explorer의 폴더·파일 구조를 최신 상태로 다시 불러올 수 있어야 한다.
- 수동 Reload는 `Ctrl+R`과 `F5` 단축키로 실행할 수 있어야 하며, Explorer와 현재 열린 문서를 다시 불러와야 한다.
- 폴더와 파일의 자동 감시는 v0.2에서 구현하지 않는다. 외부 변경 사항은 사용자가 수동 Reload를 실행했을 때 반영한다.
- Open Folder 선택 창에서 사용자가 취소하면 오류 메시지를 표시하지 않고 현재 Root Folder, Explorer, 탭 상태를 그대로 유지해야 한다.
- Explorer는 Root Folder를 고정 트리로 표시하지 않고, 현재 디렉터리의 파일과 하위 폴더 목록을 표시하는 디렉터리 이동형 탐색기로 동작해야 한다.
- Explorer 목록의 맨 위에는 항상 `..` 항목을 표시해야 한다. 현재 디렉터리가 Root Folder가 아니면 `..`을 선택하고 Enter를 눌러 Root Folder 범위 안의 부모 폴더로 이동할 수 있어야 한다. Root Folder에서는 `..`을 비활성화해 Root 밖으로 이동할 수 없도록 해야 한다.
- Windows Explorer에서 `.md` 문서를 직접 열면 해당 문서의 부모 폴더를 Root Folder와 Explorer의 현재 디렉터리로 설정해야 한다.
- Explorer에서 키보드로 선택한 항목과 키보드 포커스 위치는 마우스 hover 상태와 구분해 명확히 표시해야 한다.
- Explorer와 문서 영역 사이의 세로 구분선은 마우스 드래그로 Explorer 폭을 조절할 수 있어야 한다.
- Explorer의 기본 폭은 약 `17rem`으로 유지하고, 지나치게 좁거나 넓어지지 않도록 최소 약 `12rem`과 창 너비의 약 45% 사이로 제한해야 한다.
- 구분선을 드래그하는 동안에는 가로 크기 조절 커서를 표시하고 텍스트가 선택되지 않아야 한다. Explorer를 숨겼다가 다시 표시하면 마지막으로 조절한 폭을 유지해야 한다.
- 앱을 종료한 뒤 다시 실행했을 때 Explorer 폭을 복원하는 기능은 v0.2 범위에 포함하지 않는다.

### 8.3 탐색 대상과 열람 방식

- Explorer에는 Markdown 파일뿐 아니라 텍스트와 코드 파일도 표시되어야 한다.
- 텍스트와 코드 파일을 선택하면 내용을 읽기 전용 텍스트 뷰어로 열람할 수 있어야 한다.
- Markdown 문서의 코드 블록과 코드 뷰어는 최소한 Python, C++, TypeScript, JavaScript, JSON, PowerShell, YAML, TOML, Bash 문법 하이라이트를 지원해야 한다.
- Markdown 문서 본문은 GitHub Markdown과 유사한 읽기 스타일을 기본으로 적용해야 한다.
- 코드 블록과 코드 뷰어의 문법 하이라이트는 선택된 테마에 맞는 GitHub 계열 스타일을 적용해야 한다. White 모드에서는 GitHub Light 계열을, Dark 모드에서는 GitHub Dark 계열을 사용한다.
- 코드 블록과 코드 뷰어에는 현재 내용을 클립보드에 복사하는 버튼을 제공해야 한다.
- Markdown 문서에서 상대경로로 참조한 Root Folder 내부의 로컬 이미지는 문서 내용과 함께 표시해야 한다. 최소 지원 형식은 `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg`이다.
- 이미지 파일은 Explorer 목록에 표시하거나 단독 탭으로 열지 않는다. 이미지는 Markdown 문서 안에서 참조될 때만 표시한다.
- 로컬 이미지가 없거나 Root Folder 밖을 가리키면 이미지 대신 대체 텍스트와 오류 상태를 표시해야 한다.
- 상대경로 `.md` 링크는 Root Folder 안에 있는 대상만 앱 내부에서 열어야 한다. 대상이 이미 열린 경우 해당 탭으로 이동하고, 그렇지 않은 경우 새 탭으로 연다.
- Explorer에는 이 문서에서 확정한 지원 확장자만 표시해야 한다. 이미지 파일은 Markdown 안에서만 표시하므로 Explorer 목록에서 제외한다.
- 텍스트·코드 뷰어는 대용량 파일을 열어 UI가 멈추지 않도록 파일 크기 상한을 두고, 상한을 초과한 파일은 열지 않은 채 이유를 표시해야 한다.
- 텍스트·코드 뷰어는 바이너리 파일 징후를 감지하면 열지 않고 오류 상태를 표시해야 하며, 지원하지 않는 인코딩은 명확한 오류 메시지로 안내해야 한다.

| 구분 | 언어·형식 | 지원 확장자 |
|---|---|---|
| Markdown | Markdown | `.md` |
| 텍스트 | 일반 텍스트 | `.txt`, `.log` |
| 코드 | Python | `.py`, `.pyi` |
| 코드 | C++ | `.cpp`, `.cc`, `.cxx`, `.h`, `.hpp` |
| 코드 | TypeScript | `.ts`, `.tsx` |
| 코드 | JavaScript | `.js`, `.jsx`, `.mjs`, `.cjs` |
| 설정 | JSON | `.json`, `.jsonc` |
| 코드 | PowerShell | `.ps1`, `.psm1`, `.psd1` |
| 설정 | YAML | `.yml`, `.yaml` |
| 설정 | TOML | `.toml` |
| 코드 | Bash | `.sh`, `.bash` |

### 8.4 Windows 파일 연결

- Windows Explorer에서 설치된 앱의 아이콘 표시와 자동 뷰어 연결은 현재와 같이 `.md` Markdown 문서에만 적용해야 한다.
- 텍스트와 코드 파일은 Windows Explorer의 파일 연결 대상으로 추가하지 않으며, 사용자가 mdviewer 내부 Explorer에서 선택했을 때만 읽기 전용 뷰어로 열 수 있어야 한다.

### 8.5 테마

- White와 Dark 모드를 모두 제공해야 한다.
- 기본 테마는 White 모드여야 한다.
- Markdown 본문, 코드 블록, 코드 뷰어를 포함한 모든 읽기 영역은 선택된 White 또는 Dark 테마와 일관된 GitHub 계열 스타일을 적용해야 한다.
- 테마는 앱 최상위 요소의 `data-theme="light"` 또는 `data-theme="dark"` 값과 CSS 사용자 정의 속성으로 전환해야 한다. White와 Dark 화면을 별도로 만들지 않는다.
- Explorer, 탭, 문서 배경·텍스트·경계선, Markdown 요소, 코드 하이라이트 토큰은 모두 테마별 CSS 변수로 색상을 적용해야 한다.

| 영역 | 글꼴 | 권장 크기와 줄 높이 |
|---|---|---|
| Explorer, 탭, 버튼, 상태 표시 | `"Segoe UI Variable", "Segoe UI", "Malgun Gothic", sans-serif` | `13px`, `20px` |
| Markdown 본문 | `"Segoe UI Variable", "Segoe UI", "Malgun Gothic", sans-serif` | `16px`, `1.6` |
| 코드 블록, 코드 뷰어, 경로 | `"Cascadia Code", Consolas, monospace` | `13px`~`14px`, `1.5` |

- 파일·폴더 아이콘은 글꼴 아이콘 대신 SVG 아이콘을 사용해 기기별 글꼴 차이를 피해야 한다.

### 8.6 집중 보기

- `F11`은 운영체제 전체화면으로 전환하지 않고, 현재 Browser Window의 크기와 위치를 유지하는 집중 보기 모드를 전환해야 한다.
- 집중 보기 모드에서는 프로그램 제목 영역, 탭 영역, Explorer, 창 하단 상태바를 숨기고 문서 영역만 창 안에 표시해야 한다.
- 열려 있는 문서는 `Ctrl+Tab`과 `Ctrl+Shift+Tab`으로 전환할 수 있어야 하며, 집중 보기 모드에서도 같은 단축키가 적용되어야 한다.
- `F11`을 다시 누르면 제목 영역, 탭 영역, Explorer, 상태바를 복원해 기존 화면 구성으로 돌아와야 한다.

### 8.7 키보드 동작

| 영역 | 단축키 | 동작 |
|---|---|---|
| 탭 | `Ctrl+T` | 새 빈 탭을 생성한다. |
| 탭 | `Ctrl+Tab` | 다음 열린 탭으로 이동한다. |
| 탭 | `Ctrl+Shift+Tab` | 이전 열린 탭으로 이동한다. |
| 포커스 | `Tab` | 다음 화면 컨트롤로 키보드 포커스를 이동한다. 문서 탭 전환에는 사용하지 않는다. |
| Explorer | `↑`, `↓` | 선택한 파일 또는 폴더 항목을 변경한다. |
| Explorer | `→` | 선택한 하위 폴더로 이동한다. |
| Explorer | `←` | 현재 디렉터리의 부모 폴더로 이동한다. Root Folder에서는 이동하지 않는다. |
| Explorer | `Enter` | 선택한 하위 폴더로 이동하거나, `..` 항목을 통해 부모 폴더로 이동한다. 선택한 파일은 연다. 파일이 열린 탭에 없으면 새 탭에 열고, 이미 열린 파일이면 해당 탭으로 이동한다. |
| 갱신 | `Ctrl+R`, `F5` | Explorer와 현재 열린 문서를 수동으로 다시 불러온다. |
| 집중 보기 | `F11` | 현재 창 크기와 위치를 유지한 집중 보기 모드를 전환한다. |

### 8.8 상태바

- 창 하단 상태바에는 현재 활성 탭에서 열린 문서 또는 텍스트·코드 파일의 전체 경로를 표시해야 한다.
- 빈 탭에서는 파일 경로가 없음을 표시해야 한다.
- 상태바는 일반 보기에서만 표시하고, 집중 보기에서는 숨겨야 한다.

### 8.9 읽기 영역 글꼴 크기

- 사용자는 Markdown 본문, 텍스트 뷰어, 코드 뷰어, Markdown 코드 블록의 글꼴 크기를 조절할 수 있어야 한다.
- 글꼴 크기 확대는 `Ctrl` + `+` 및 `Ctrl` + `=`로, 축소는 `Ctrl` + `-`로 실행해야 한다.
- `Ctrl` + 마우스 휠 위·아래는 각각 글꼴 크기를 확대·축소해야 한다.
- `Ctrl` + `0`은 기본 글꼴 크기로 복원해야 한다.
- Explorer, 탭, 버튼, 상태바 등 앱 조작 UI의 글꼴 크기는 조절 대상에 포함하지 않는다.
